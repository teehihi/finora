## Delivery sequence, representative effort and release blockers

| Milestone                   | Work and gate                                                                                                                                                                                                        | Planning effort only                    |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Discovery and technical map | Identify a single primary journey, behavior edge cases, existing route/data authority, baseline revision and current gaps.                                                                                           | 0.5 day                                 |
| UX                          | Map five journeys, grayscale layouts, distinct estimate/track language, then keyboard and first-time walkthrough; code stays untouched.                                                                              | 1–2 days                                |
| UI                          | Test three differing art directions, six signature high-fidelity screens, shared token roles, Vietnamese labels and meaningful state variants; internal review does not equal owner approval.                        | 2–3 days                                |
| Implementation              | Tokens → existing shared components → Home → Fin → Simulator → Explore → sign-in/onboarding → detail/documents → repayments/profile → web entry; retain a render/interaction checkpoint after each meaningful slice. | 2–4 days                                |
| QA and acceptance           | Synthetic local PostgreSQL + Mailpit, existing checks, compare prototype/base/actual at 360/390/430/768/1024/1440, dark and light, then owner checklist and native checks where possible.                            | 1–2 days plus owner/device availability |

Mobile: prioritize action reach, safe area and keyboard/show-hide dock. Tablet: let related columns grow only when task hierarchy remains legible. Desktop: preserve sidebar and bounded content; side-by-side comparisons and results are useful but not forced on phone. Keep native scroll, reduced-motion fallbacks, logical focus and native labels. At narrow widths/large text, allow wrapping instead of decreasing text or clipping financial amounts. Show source, missing fee and manually tracked status in text, not color only.

Risk owners: UX/QA verify estimates versus actual debt; design/QA confirm font coverage and state hierarchy; engineering/QA verify no drift in assumptions, owner isolation or live data handling; owner approves final experience. Mitigations: reuse verified tests, review copies of visual artifacts, and capture from the exact app revision. If native simulator or hardware is unavailable, web/exports are not proxy evidence. No live OCR/AI/OAuth verification is implied by mocked flows. Retain CI and the PR-description rule. Publish only on a separate branch when authorized; do not merge or deploy.

**Gate:** Existing architecture supports the intended work. No changed backend dependencies or production provisioning proposed. Estimates are planning ranges, not commitments. Native input/assistive interactions and owner UAT remain outside this technical review.

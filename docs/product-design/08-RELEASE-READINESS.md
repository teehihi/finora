# 08 · Release readiness

**Status: production release deferred.** This document prepares decisions, not a deploy. Do not provision, publish, change production data or buy services during the design sprint. Base information: [README](../../README.md), `.env.example`, `apps/api/.env.example`, `apps/app/.env.example`, [architecture](../architecture/ARCHITECTURE.md), [security](../../SECURITY.md) and [design-sprint implementation plan](03-IMPLEMENTATION-PLAN.md). Neither this inventory nor successful local verification establishes production readiness.

## Local review

Use Node 22 and pnpm 10.32.1 with `pnpm run setup` in a checkout, then `pnpm dev`. Preserve the standard Compose PostgreSQL/Mailpit setup. Use a disposable test database and upload directory, synthetic users and files, and Mailpit OTP. Never reset a shared volume to get a clean test; use separate storage/testing configuration. `pnpm run format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` and configured `pnpm test:e2e` are checks, not deployment steps. Use [verification docs](../VERIFICATION.md) for fixture setup and the current sprint QA report for actual evidence.

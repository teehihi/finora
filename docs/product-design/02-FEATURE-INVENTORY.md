# 02 · Feature inventory

**Objective:** Prioritize outcomes rather than routes. Evidence comes from `apps/app/app`, `apps/api/src/modules`, `tests/e2e` and the [verified V5 report](../VISUAL_EXCELLENCE_REPORT.md). Tests named below are baseline coverage, not a rerun in this phase.

| Capability (demo scope)               | Problem and useful outcome                                     | Entry; inputs → output                                                                                                              | Implementation, dependency and invariant                                                                                                     | Failure / acceptance condition                                                                                                                                                    |
| ------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public welcome and tour (Must)        | Judge relevance before account setup.                          | `/auth` → `/showcase`; illustrative scenario → educational cost.                                                                    | Public sample; no authenticated data or personal quote.                                                                                      | Still useful without a session; sign-in is an explicit exit. `auth.spec`                                                                                                          |
| OTP / sessions / recovery (Must)      | Start safely and return without input loss.                    | `/auth`; email + received OTP → owned session.                                                                                      | Better Auth email via Mailpit; provider status and legacy paths preserved.                                                                   | Invalid/retryable/unavailable distinguishable; already accepted code not sent twice; unknown provider not clickable. `auth.spec`                                                  |
| First-run onboarding (Must)           | Start without sharing everything.                              | Empty Home → optional `/profile`; choose edit or skip → visible next task.                                                          | Session-backed Home; no invented budget.                                                                                                     | Empty/reset/error states remain actionable; Explore/Fin available without a financial profile. `v4-home.spec`, `journey.spec`                                                     |
| Profile & capacity (Must)             | Assess room after recurring commitments.                       | Home/Profile; stated income, expenses, debt, savings → stated inputs, cash remaining and indicative capacity.                       | `PUT /api/profile`, server account, shared engine; capacity and cash are separate.                                                           | Invalid inputs stay editable; missing profile not a meaningful zero; never display as approval. `v4-home.spec`, `journey.spec`                                                    |
| Finora AI guided planning (Must)      | Ask in everyday Vietnamese, verify the results.                | Dock Fin → `/assistant`; question and confirmed assumptions → grounded output and next action.                                      | `/api/intelligence/*`, typed tools, owned local context, optional per-turn external interpretation; `/intelligence` retains manual analysis. | Ask for essential missing assumptions; safe cancel/retry; no silent saved plan, external payload or profile update. `intelligence-workspace.spec`, `intelligence-backend.spec`    |
| Explore / offer details (Must)        | Scan usable products without misleading precision.             | `/explore`; search/filters and selected published product → details, source and status.                                             | Portfolio uses catalog/reviewed terms, with sample route distinct from personal terms.                                                       | Empty filter recovery; unavailable terms identified instead of implied. `public-catalog.spec`, `v4-market.spec`                                                                   |
| Compare (Must)                        | Avoid comparing unlike amounts or terms.                       | Explore within comparison context; same amount/term and each interest basis/fee input → A/B schedule and uncertainty.               | Shared engine; unknown fees block total-cost rank.                                                                                           | Explain incompatible assumptions or missing figures; editable comparable assumptions. `personal-simulator.spec`, `simulator.spec`                                                 |
| Simulate (Must)                       | Understand timing and first/total known cost.                  | Explore, direct calculator, Fin or reviewed docs → `/simulate/:id`; own terms, basis, fees → first payment, known total and ledger. | Preview uses server engine; changing personal terms never quietly inherits advertised terms.                                                 | Validation, service error, and missing fees have distinct output or recovery. `v4-market.spec`, `personal-simulator.spec`                                                         |
| Review contract (Should)              | Understand extracted evidence and correct uncertain values.    | Home/Fin → `/documents`; synthetic PDF/image plus confirmation → extracted candidates or manual input with preview.                 | `/api/document-analysis`, local storage with ownership first; optional local OCR; no implicit external inference.                            | Unsupported/failed extraction supports manual review; asset/delete only visible to owner; keep unconfirmed candidates out of save. `document-intelligence.spec`, `ownership.spec` |
| Save & revisit estimate (Must)        | Preserve a set of assumptions for later.                       | Simulator, Fin or document preview; explicit save → snapshot under `/saved/:id` via `/loans`.                                       | Owned immutable terms and result saved together via existing APIs; no tracked obligation implied.                                            | Cancel creates nothing; snapshot displays uncertainty and original inputs. `personal-simulator.spec`, `intelligence-workspace.spec`, `repayments.spec`                            |
| Track a confirmed loan (Should)       | Make actual obligations distinct from saved plans.             | Saved detail after signing; reviewed inputs and real first due date → tracked ledger.                                               | `POST /api/repayments`; confirmation explicit; status manual, not imported.                                                                  | Cancel/validation creates no track; reloading an estimate alone never adds a due date. `repayments.spec`                                                                          |
| Manage repayments (Should)            | Know next payment, find progress and record completed payment. | Loans/Home next payment → `/repayments`; select period, confirm actual status → owned updated record.                               | `GET /api/repayments`, `PUT /api/repayments/:id/payments/:period`; no money movement.                                                        | Confirmation and after-reload persistence; empty and failure distinguishable. `repayments.spec`                                                                                   |
| Settings, privacy and sign-out (Must) | Control accessibility aids, language, data and session.        | `/profile`; appearance/language/history selection → explicit saved preference or scoped deletion/sign-out.                          | Account/preferences APIs and scoped history stores; session & query isolation.                                                               | Cancel destructive actions unchanged; one history delete does not erase the other or the profile. `profile-privacy.spec`, `layouts.spec`                                          |

**Gate:** Every primary destination supports a named job; remaining capabilities are contextual, not proposed new tabs. Inferred user desirability and new layouts still need walkthrough/UAT. No existing features are removed by this classification.

# FINORA Intelligence 3.0: research and design decisions

Reviewed 2026-11-25. Desk research using public first-party product material, regulator consumer-education pages, official provider docs and OWASP guidance. Not a logged-in product study, legal review, model benchmark, or claim that cloud credentials are available.

## Starting point and priorities

At repository base `230caf2`, the Nest assistant exposed authenticated history and an SSE stream with idempotent request IDs and a request timeout. Its only configured provider was the text-streaming `MockProvider`; simulation facts were already computed via the owned Planning service. Keep those ownership boundaries and the existing Expo design system. Keep the financial engine authoritative. Complete the sign-in → question → missing input → affordability and comparable offers → scenario → review synthetic document → save → schedule path before extending reminders, managed infrastructure, or AI framework integration.

## Local-first application boundary

1. **Collect only necessary information.** Let an authenticated backend load a minimal owned profile. Prefer derived facts or bucketed internal context, never pass account identifiers, contact details, logs, whole conversation histories, or documents to a provider by default. Tell users when inputs will leave the app. No IDs, bank credentials, or credit files are needed. Interpret absence as unknown, not zero.
2. **Model proposes; Nest authorizes and executes.** Use a fixed read-only allowlist with strict schemas. Known tool names do not imply permission. Derive ownership from session, never the proposed call. Verify each result schema; normalize error categories. Do not expose arbitrary requests, arbitrary code, arbitrary datastore access, or external sends to the model. Write effects use an existing authenticated UI/server action with explicit confirmation.
3. **Ground every number.** Use safe canonical VND integer amounts, integer months, explicit annual percentages and calculation methods. Rank only truly comparable offers with compatible boundaries and terms. Separate principal plus interest from all-in cost. Unknown fee, insurance, benchmark or prepayment penalty stays unknown. Forecast means “estimate under these assumptions,” not certainty, lender rate, eligibility, or approval. Use highest applicable installment rather than the advertised minimum when testing stress.
4. **Control what renders.** Stream progress and safe explanatory text; admit numeric result blocks assembled from validated owned tool records. Resolve provenance from catalog snapshot and timestamp. Model identifiers cannot directly become navigation links or arbitrary markup. In the mobile ledger keep the conclusion, why, assumptions, and source next to each other.
5. **Retrieve without a new platform.** Query the reviewed local catalog with normalized category, purpose, eligibility constraints, amount and term. Use no automatic crawling, embeddings, or external model web tools for P0. If no candidate fits, say so and expose the constraints; no arbitrary fallback. Treat source revisions, quotes, scanned offers and modeled estimates differently.
6. **Bound and observe.** Cap context, tokens, rounds, upload bytes/pages, rates and runtime; use abort propagation and bounded retry only for transient failures, not after user-facing deltas or writes. Record provider/model, token counts when reported, durations, tool names/outcomes and safe error categories. No raw prompts, exact personal numbers, uploaded text, secrets or full responses in operational logs.

## Documents and review

Use deterministic per-page PDF text first ([PDF.js page text API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)). Where text is missing, offer manual review or configured OCR/multimodal extraction after meaningful opt-in. Neither provider extraction nor OCR proves the terms are complete or correct. Rescan structured amounts, terms, method, fee applicability and early-payment conditions against source page excerpts. Preserve contradictions or illegible values as unresolved. Allow the owner to correct and explicitly confirm versioned terms before they can populate a simulator. Attribute amounts to **extracted** or **user-corrected** evidence, separate from calculator output. Reject invalid media, unreasonable dimensions and oversized uploads; do not run document scripts or follow embedded instructions or links. Only authenticated owners may review or delete their own documents. Use synthetic fixtures only in external demo and evaluation.

See [the evaluation protocol](../evaluation/README.md) for reproducible measurement rather than a claimed vendor benchmark.

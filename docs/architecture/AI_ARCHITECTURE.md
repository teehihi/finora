# Finora Intelligence architecture

Finora runs a deterministic local assistant by default. The optional server-side OpenAI-compatible Responses adapter activates with `AI_PROVIDER=openai`, or the native Anthropic Messages adapter with `AI_PROVIDER=anthropic`, and a server-only key. Each external request still requires explicit consent in the chat UI. The configured provider sees only the redacted current question and neutral tool acknowledgements; it does not receive saved profiles, uploaded files, account IDs, prior turns or engine outputs.

`IntelligenceController` derives the user ID from the Better Auth session guard, loads only owned data, merges versioned conversation context and authorizes registered read-only operations. Provider proposals are validated against Zod schemas, including bounded parallel read-only calls. The provider cannot execute writes. A profile update is proposed as a typed card and requires a separate confirmation through the guarded profile route. A scenario is saved only through the separately confirmed `scenarios/save` route. An attached document ID is owner-checked before a private summary card is built; extracted text never enters the model request. The existing financial engine produces loan schedules and comparisons; the model contributes no financial arithmetic. The server renders typed result cards and missing information. A bounded, qualitative model sentence can supplement the local explanation after a claims guard. A failed or unsafe provider response produces a disclosed local fallback.

POST SSE emits `progress`, `meta`, `delta`, `structured` and `done` events. Progress stages label provider, profile, public catalog and calculation work without exposing private values. Client cancellation aborts the upstream request; completed turns are persisted per user and retries reuse a request ID. The orchestration limits rounds, output size, time and per-user requests. SSE streams the validated Finora answer after provider completion; upstream model token streaming is not enabled. Provider endpoints and retry settings are documented in [OPENAI_PROVIDER.md](OPENAI_PROVIDER.md). The product flow and current limitations are in [INTELLIGENCE.md](INTELLIGENCE.md).

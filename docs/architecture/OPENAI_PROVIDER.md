# Optional external AI providers

Finora is local-first. Keep `AI_PROVIDER=mock` to run without credentials or any upstream model requests. The optional OpenAI adapter lives only in NestJS. To opt in, use the API environment template, choose `openai` and supply your own server-side OpenAI key and supported model, never Expo's public variables. No account, credentials, provider-side resource or deployment is provisioned by this project.

For the native Anthropic Messages API or a compatible gateway, set `AI_PROVIDER=anthropic`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL` and optionally `ANTHROPIC_BASE_URL` in `apps/api/.env`. The default base URL is `https://api.anthropic.com`; `/v1/messages` is appended. `ANTHROPIC_TIMEOUT_MS`, `ANTHROPIC_MAX_OUTPUT_TOKENS`, `ANTHROPIC_RETRY_COUNT` and `ANTHROPIC_RETRY_DELAY_MS` have the same bounds as the OpenAI settings. The Anthropic adapter uses the `x-api-key` and `anthropic-version` headers, never a client variable. For Claude Sonnet 5 it requests disabled thinking; compatible gateways may ignore this. Finora validates up to four parallel read-only tool proposals and replays every matching result. A thinking block, if returned during a tool round, is replayed unchanged only within that request and is never persisted or displayed. The authenticated model metadata probe reports unknown when a gateway returns 404 or 405. See the [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create) and [thinking behavior](https://platform.claude.com/docs/en/build-with-claude/thinking).

Run `pnpm exec tsx scripts/verify-anthropic-live.ts` from `apps/api` only when a valid token is already configured and synthetic live verification is desired. The script prints no token, prompt, response text or private data. `FINORA_LIVE_AI_TEST=1 pnpm test:e2e tests/e2e/intelligence-live.spec.ts` checks the authenticated local and consented path against a running API.

The adapter accepts a compatible Responses API at `OPENAI_BASE_URL` (default `https://api.openai.com/v1`). Configure `OPENAI_MODEL`, `OPENAI_TIMEOUT_MS`, `OPENAI_MAX_OUTPUT_TOKENS`, `OPENAI_RETRY_COUNT` (0–3) and `OPENAI_RETRY_DELAY_MS` (0–2000). Only HTTPS endpoints and loopback HTTP endpoints are accepted; credentials, query strings and fragments in the URL are rejected. Retry applies only to timeout, rate limit and transient availability errors. The authenticated `GET /api/intelligence/health` checks the configured model endpoint without sending a conversation. Some compatible hosts may not implement `GET /models/{model}` even when inference works; in that case a failed health probe does not disable local analysis.

[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) supports the Responses endpoint, function calls, and `reasoning.effort: none`, making it a suitable default for this bounded local tool flow. The adapter explicitly sets that mode for GPT-5.4 mini/nano. Models that emit reasoning items alongside function calls require ordered replay of the result including opaque encrypted reasoning. Finora does not retain or replay those items, so that model/turn is rejected rather than running an unverifiable continuation. See [function calling](https://developers.openai.com/api/docs/guides/function-calling) and [reasoning in stateless mode](https://developers.openai.com/api/docs/guides/reasoning#preserve-reasoning-without-stored-responses).

## Trust boundary

- Server-only POST to the configured Responses endpoint with redirects disabled. `store: false`, no model-side conversation ID, built-in tools, web search, file uploads or background mode.
- The caller supplies only the redacted current question and neutral tool acknowledgements. Do not supply raw loan files, identity data, account identifiers, credentials, or unrelated financial history. Enabling a remote provider sends allowed content outside Finora's local environment. `store: false` opts out of stored response state; it does not remove all applicable provider abuse-monitoring retention. Review [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) before using real data.
- The provider can return final text or up to four registered read-only function proposals in a round. It never runs functions, authorizes data access, or treats response text as facts. The application validates every argument against the tool's domain schema, enforces ownership, runs the existing local financial engine and retains provenance separately.
- After explicit per-message consent, the model may contribute one short qualitative sentence to the answer. The server rejects model text containing numbers, currency, percentages, links or eligibility claims. Financial figures, missing fields and source cards come from local validated logic. Unsafe wording is withheld and a neutral recovery completion may be requested. An unavailable or invalid provider triggers a disclosed local fallback; validated tool selections can remain labeled as live even if no model sentence is shown.
- Per request: 32 logical messages, 12 declarations, 64 KiB JSON input, at most four calls per round, 4 KiB arguments per call, 256 KiB upstream response and 16 KiB final text. The default is 12 seconds and 600 output tokens; the boundaries are 1–30 seconds and 16–4,096 output tokens. The orchestration also bounds tool rounds.
- Errors expose a safe code and optional numeric HTTP status, not provider response bodies, keys or model explanations. Cancellation, timeouts, rate limits, refusal and incomplete output are distinct. Completed responses report the actual reported model and optional input/output/total token counts; application streaming is separate from the provider's bounded completion.

## Local verification without a key

```sh
pnpm --filter @finora/api test -- intelligence-provider.test.ts
```

This suite injects a local fetch mock and verifies the request contract, a tool proposal and continuation, bounded parsing, sanitized errors and cancellation. It does not connect to OpenAI or verify live credentials, account entitlements, billing, or an upstream model's answers.

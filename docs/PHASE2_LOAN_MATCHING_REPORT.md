## Limits and release work

1. The six reviewed public records cannot produce a verified product-level monthly schedule or complete borrowing cost. The engine supports complete synthetic fixtures, but no real lender product is recommended as suitable until sourced terms are added and reviewed. A personal quote and lender decision still require the lender.
2. Eligibility documents, employment conditions, collateral and insurance requirements are currently free text. Without a structured, sourced rule and corresponding user fact, the engine reports insufficient information. It does not infer approval or rejection.
3. Weights and the 35% planning threshold are configurable assumptions, not validated credit-risk parameters. The default income stress is 20%. No credit model was trained.
4. Native iOS/Android safe areas, fonts, tap targets and interaction were not run on a device or simulator. Owner UAT and a source refresh are needed before release. The existing Chrome web app and local API are the tested platforms.
5. The matching tool intentionally does not send private profile, saved history, matching scores or engine results to the external LLM. Product-level explanations are deterministic. A future model-generated explanation would need a privacy-approved, grounded payload and independent claim validation.

No production account, OTP, real contract, lender decision or private financial record was used in tests. See [matching architecture](architecture/LOAN_MATCHING.md) for formulas, classification and API behavior.

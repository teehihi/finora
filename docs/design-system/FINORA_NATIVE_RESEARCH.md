# Finora Native: iOS research and design decision

**Reviewed:** 26 November 2026. **Scope:** authenticated Finora Home at an iPhone width, plus the existing shared dock.

## Current UI audit

The verified starting point was `main` at `bea9fbd0626dd21708dccb8b9a18aae23d6d2f91`, with a clean worktree. `ART_DIRECTION.md` and the existing design exploration describe the rejected financial notebook/editorial direction; they are historical material and are not a current visual specification.

The current Home already loads the user's account through `useAccount()` and saved simulations through the authenticated `api.saved` client, then scopes the saved query key by session user ID. It shows a useful repayment capacity estimate (or profile prompt), saved simulations, links to Explore and AI, and an honest no-active-repayment message. Its presentation starts with a large serif greeting/description, a large forest feature card, uppercase micro-labels, and divider-led sections. On a phone this makes the screen feel like a long-form page rather than a daily-use app.

The workspace shell provides a compact brand header and profile action, safe-area and keyboard handling, responsive web rail layouts, and a five-item draggable dock. The dock's PanResponder, animated selected indicator, release navigation, tap actions, reduce-motion behavior, keyboard visibility behavior, accessibility roles/labels, iOS Liquid Glass, and cross-platform surface are existing approved behavior. The redesign keeps that interaction implementation intact.

Relevant existing flows: Home → Profile to add/edit a financial profile; Home → Explore to start a simulation; Home → AI; Home → Loans and `/saved/:id` for saved simulations. Upcoming repayments are deliberately not invented; current copy says there are no active repayment schedules. The current Home has no dedicated component test; saved-scenario navigation is covered by `tests/e2e/journey.spec.ts`, and shell layouts by `tests/e2e/layouts.spec.ts`.

## Apple HIG takeaways

- **Layout and safe areas:** use system safe areas, adaptive margins, and progressive disclosure. The Home scrolls vertically and lets the shell own its dock inset.
- **Typography and Dynamic Type:** use a restrained system sans and tabular numerals for monetary amounts. Let labels wrap; avoid fitting text by shrinking it. The Home's primary number is data, not a display headline.
- **Navigation:** keep labels on persistent destinations. The draggable dock is a product-specific interaction with an accessible tap path; its shell behavior is preserved.
- **Materials:** Apple's current guidance defines Liquid Glass as a functional control/navigation layer. Keep it on the dock where supported; use a solid, high-quality fallback elsewhere and avoid glass cards.
- **Accessibility and interaction:** preserve accessible names and selected state, contrast, touch targets, keyboard avoidance, and a reduced-motion path. Core navigation remains available by both tap and drag.
- **Sheets and charts:** [Apple's sheet guidance](https://developer.apple.com/design/human-interface-guidelines/sheets) favors focused tasks with clear dismissal. Avoid adding a chart to Home without enough real data to make it informative.
- **Haptics:** [Apple recommends](https://developer.apple.com/design/human-interface-guidelines/playing-haptics) short, optional haptics for discrete events. No new haptics are introduced here because the current custom dock has no haptic contract and this scope does not require adding a new native dependency.

## Three Home explorations

The three 390px design previews are in `docs/design-system/previews/finora-native-concepts.html`. Amounts and saved-simulation details are explicitly labeled fixture data; they are not wired into the app. The UI capture surface refused local-file previews, so rendered concept screenshots remain outstanding.

1. **A — Native Minimal (selected):** open canvas, warm restrained greeting, an unboxed large tabular estimate with its assumptions, one primary simulation action, a compact AI shortcut, and a short saved-scenarios list. This prioritizes scanning and makes the number feel like useful information rather than a credit score.
2. **B — Modern Fintech:** tighter dark-green financial summary, a modest progress indicator, and a paired action strip. This is more energetic and number-led, but risks making a self-reported planning estimate look like a bank balance or approved limit.
3. **C — Warm Premium:** richer sage/ivory surfaces with a friendly greeting and a single prominent action. It carries more brand warmth, but creates heavier surfaces and places more emphasis on the brand color than daily utility needs.

The concepts use the same fixture content to compare hierarchy. The implemented Home selects A, but replaces fixture values with the real existing account and saved-simulation responses, including the no-profile empty state. No competitor layout or artwork is copied.

## Verification limits

- `pnpm run setup` completed with the existing PostgreSQL volume; no database reset was run. App unit tests, typecheck, lint, formatting, the Expo bundled-native version check, and an iOS Debug build succeeded.
- The authenticated web journey did not reach Home: its existing password sign-in displayed the generic connection/sign-in error, including when both app and Better Auth URLs were overridden to `localhost` for the run. Home, tap/drag dock assertions, and the mobile screenshot assertions therefore remain unverified in E2E.
- The iOS build installed, but the headless host has no Simulator.app UI. The dev-client URL triggered an iOS “Open in Finora?” confirmation which could not be accepted here, so an authenticated native Home render was not captured. `adb devices` returned no Android emulators.
- The CUA browser blocks local-file URLs and disallows using another browser path to work around that restriction. The concept HTML previews are available, but their rendered screenshots, the before/after captures, and the three visual review rounds remain outstanding.

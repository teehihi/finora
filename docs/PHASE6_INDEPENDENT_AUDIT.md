# FINORA Phase 6 independent audit

28 November 2026. Baseline: `f246f14` on `codex/phase6-readiness`. This review inspected the committed Phase 6 diff, API and UI call paths, contracts, Prisma schema and migration list, financial engine, AI providers, evaluation fixtures, deployment recipe and tests. No Phase 6 schema migration was added. All executed accounts, prompts, documents and databases were synthetic. A passing finite suite does not prove real-world financial accuracy or security.

**Release decision: do not deploy publicly or claim Phase 6 production readiness.** Development may continue on this branch with the audit fixes below. The live credential exposed in an earlier local test log must be revoked and rotated before any further provider verification.

## Confirmed fixes from this review

1. `tests/e2e/phase6-evaluation.spec.ts` calculated `passed` for each case but asserted only SSE schema validity and a terminal event. A wrong result kind could leave the test green. The test now asserts every case result and the correct local/live provider, and records the model ID when live mode is explicitly enabled. Negative control: deliberately changing D01's expected kind made the test fail on `local:D01`; restoring it made the local test pass 1/1. The live branch was not run with the exposed credential.
2. `deploy/.env.production.example` contained literal replacement passwords and an auth secret, yet the production API started with that file in an isolated Compose smoke test. `apps/api/src/config/env.ts` now rejects the example auth secret, an example or short database password, and a database URL without a sufficiently long password. `apps/api/test/production-env.test.ts` failed before the fix and passed 7/7 after it. This guard detects the supplied examples and minimum length; it cannot prove a secret is random.
3. The optional Mailpit E2E initially timed out because Playwright reused a development API started with email reminders disabled. `tests/e2e/proactive-repayment.spec.ts` now checks the authenticated email capability explicitly. Restarting the local API under `FINORA_REMINDER_EMAIL_ENABLED=true` made the opt-in test pass 1/1; the normal local API was restored afterward.

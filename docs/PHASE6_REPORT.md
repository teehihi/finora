# FINORA · Phase 6 verification report

Date: 28 November 2026. Branch: `codex/phase6-readiness`. This report records synthetic local and consented synthetic-provider checks. It does not authorize a public release or claim absolute financial/security correctness.

## Changes

- Production API configuration now accepts `NODE_ENV=production` only with HTTPS origins, TLS SMTP, persistent absolute document storage, HTTPS active AI endpoint and one explicitly trusted private reverse-proxy hop. A legacy synthetic document can be deleted only by its owner; foreign access remains 404.
- Better Auth and its Expo plugin were updated together to 1.7.7, Nodemailer to 10.0.6, Vitest to 5.1.2, and Effect pinned to 3.22.1. The new Better Auth Expo cookie API is awaited in the API client, document and Fin transports. Financial formulas were not changed; a separate representative formula cross-check was added.
- Added labeled development/holdout parser evaluation, a Local/Live synthetic API evaluation, and a single-host Docker/Caddy reference with persistent PostgreSQL and document volumes, committed migrations, Vietnamese/English OCR dependencies, health checks and a backup procedure.
- Corrected the search safe-area color and Fin menu anchor on mobile web, and updated the repayment journey test to the Phase 5 preparation route. No navigation or visual redesign was made.
- Corrected a financial-engine source import that prevented Expo Metro from bundling iOS and Android. The financial formulas and ranking policy were unchanged.

## Risks and next steps

1. Revoke and rotate the exposed Claude token. Review access logs before public use. Never store real contracts, credentials or OTPs in evaluation traces.
2. Resolve the remaining Prisma/transitive advisory through a tested Prisma upgrade or documented acceptance, then rehearse a database and document-volume restore on separate infrastructure.
3. Run public HTTPS, OAuth callback, SMTP delivery, Caddy proxy/IP rate-limit, scheduler, storage-permission and backup checks with real deployment credentials. One API replica is the only supported configuration until rate limits and reminder scheduling use shared state.
4. Run native iOS/Android development builds and device UAT, including safe area, Vietnamese font, focus and accessibility. Expand holdout AI/document datasets and record actual tool-call traces without leaking profile or document contents.

The deployment recipe and exact commands are in [DEPLOYMENT.md](architecture/DEPLOYMENT.md); the [security audit](PHASE6_AUDIT.md) records the prioritized findings. The [three-minute demo](DEMO_PHASE6.md) uses synthetic data and distinguishes local from live AI.

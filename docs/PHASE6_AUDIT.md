# Phase 6 audit and release evidence

The repository is a local-first financial education application. This review inspected Expo UI and API client, NestJS routes, Better Auth, Prisma schema and migrations, deterministic financial engine, matching, Digital Twin, OCR/extraction, repayment and notification services, tests and existing documentation. The existing 33 Vietnamese AI scenarios were specifications rather than measured outcomes. Four seeded products are synthetic and must remain labeled as such.

Two further P1 findings arose during verification. A failing production configuration test serialized the parsed environment into a local test log, exposing a configured provider token. The test now returns only non-sensitive fields and blanks credentials before import. The token owner must revoke and rotate it before public use; deleting a log cannot invalidate a token. Separately, a reverse-proxied API would have grouped all clients into one rate-limit bucket. Production now requires `TRUST_PROXY_HOPS=1` and the API port remains private to the Caddy network. Directly publishing port 3000 would invalidate that trust boundary.

No cross-user access was observed in the owner-scoped E2E checks. A finite suite cannot prove that all access-control paths are safe. Uploaded document text stays untrusted; external provider receives only a redacted current prompt after per-request consent, not saved profiles, histories or documents. A user can still type personal data into a current prompt; redaction is limited and should be reviewed before public launch. API keys remain server-only. Review production logs, backup encryption, data deletion and incident response with an operator before launch.

The authentication upgrade follows the [Better Auth critical advisory](https://github.com/better-auth/better-auth/security/advisories/GHSA-965c-763c-88jm) and keeps its Expo integration at the same release. Test currently configured OTP/password flows and any enabled Google/Apple OAuth callback again during deployment; the latter cannot be proven with synthetic local credentials.

## Evaluation protocol and result boundaries

`docs/evaluation/intelligence-vi.json` contains 33 synthetic Vietnamese scenarios. `phase6-intent-labels.json` explicitly labels 11 of them: 4 development and 7 holdout. `pnpm --filter @finora/api exec tsx scripts/evaluate-intent.ts` writes a gitignored JSON report under `.data/evaluation/`. It measures **deterministic pre-orchestration** field parsing and whether tools are offered, not a trained classifier or actual LLM tool selection. `tests/e2e/phase6-evaluation.spec.ts` measures four synthetic API scenarios in two splits, records schema validity, observed result kind, exact engine reconciliation for any scenario, terminal SSE state, provider and end-to-end latency. Set `FINORA_LIVE_AI_TEST=1` only with an authorized configured provider; consent is true only for these synthetic prompts. Live mode is a single trial per case, not a statistical estimate.

Document extraction metrics are produced independently by `apps/api/test/document-evaluation.test.ts` and `document-ocr-evaluation.test.ts`, with development/holdout fixtures. Browser E2E tests cover authorization, injection, matching, repayment, notifications and other journeys. Their pass counts are test outcomes, not prevalence or real-world error rates. Do not combine deterministic parser, OCR and live model denominators into one accuracy figure. See the Phase 6 report for measured commands and failures.

## Release decision

The code is **not yet verified for public production**. Public HTTPS and SMTP delivery, encrypted off-host backup with restore rehearsal, native device testing, representative live evaluation, privacy/retention policy and operator monitoring are outstanding. The deployment reference intentionally creates no paid resources and performs no production data migration.
